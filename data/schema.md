Recourse Dataset Schema

Each record represents one synthetic chargeback case.

The dataset contains two categories of information:

1. Observable features — information available to Recourse when making a decision.
2. Hidden outcome information — information used only for evaluation.

The prediction system must never receive the hidden outcome fields.

⸻

1. Transaction Features

amount

Chargeback amount in INR.

* Type: float
* Example: 4999.00

transaction_age_days

Number of days between the original transaction and the chargeback.

* Type: integer
* Example: 27

payment_method

Payment method used for the transaction.

* Type: categorical
* Values:
    * card
    * upi
    * netbanking
    * wallet

⸻

2. Customer Features

account_age_days

Age of the customer’s merchant account.

* Type: integer

previous_orders

Number of previously completed orders.

* Type: integer

previous_chargebacks

Number of previous chargebacks associated with the customer.

* Type: integer

previous_refunds

Number of previous refunds associated with the customer.

* Type: integer

⸻

3. Transaction Behaviour Features

device_seen_before

Whether the device has previously been associated with the customer.

* Type: boolean

location_consistent

Whether the transaction location is consistent with the customer’s historical behaviour.

* Type: boolean

velocity_24h

Number of transactions associated with the customer/device in the previous 24 hours.

* Type: integer

⸻

4. Fulfillment Features

delivered

Whether the merchant records indicate that the order was delivered.

* Type: boolean

delivery_confirmed

Whether there is stronger delivery evidence such as confirmation, OTP, signature, or equivalent proof.

* Type: boolean

delivery_age_days

Number of days between confirmed delivery and chargeback.

* Type: integer

⸻

5. Merchant Interaction Features

customer_contacted

Whether the customer contacted the merchant before filing the chargeback.

* Type: boolean

merchant_response_time_hours

Time taken by the merchant to respond to the customer’s complaint.

* Type: float

refund_requested

Whether the customer explicitly requested a refund before filing the chargeback.

* Type: boolean

⸻

6. Dispute Features

dispute_type

The primary dispute category.

* Type: categorical
* Values:
    * ITEM_NOT_RECEIVED
    * UNAUTHORIZED_TRANSACTION
    * PRODUCT_NOT_AS_DESCRIBED

dispute_text

Unstructured customer dispute description.

* Type: string

This field will later be used to demonstrate where an LLM adds value by extracting structured information.

⸻

Hidden Evaluation Fields

These fields are generated by the ground-truth outcome simulator and are NOT provided to the prediction system.

actual_defensible

Whether the merchant would ultimately have a defensible case based on the simulated underlying outcome.

* Type: boolean
* Evaluation only

actual_won

Whether the merchant would actually win the simulated dispute if defended.

* Type: boolean
* Evaluation only

actual_recovery_amount

Amount recovered if the dispute is successfully defended.

* Type: float
* Evaluation only

defense_cost

Estimated cost incurred by defending the dispute.

* Type: float
* Evaluation only

⸻

Important Evaluation Rules

No label leakage

The prediction system must not receive:

* actual_defensible
* actual_won
* actual_recovery_amount
* any field derived directly from these values

Independent outcome generation

The hidden outcomes must be generated separately from the model’s prediction logic.

The outcome generator should represent a noisy simulated underlying world rather than simply applying the same rules used by the classifier.

For example, we must avoid:

delivery_confirmed = true
        ↓
actual_defensible = true

because this would make the prediction task trivial.

Train / validation / test separation

The dataset will eventually be divided into:

* Training set
* Validation set
* Held-out test set

Model parameters and decision thresholds must be selected using training/validation data only.

The held-out test set must remain untouched until final evaluation.
